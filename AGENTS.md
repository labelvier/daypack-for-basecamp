# Development Guidelines for Basecamp Kanban Filter

## Project Overview

Browser extension (Chrome + Safari) that adds filtering capabilities to Basecamp 4 card tables (kanban boards). The extension runs as a content script on Basecamp pages, adding assignee, author, and tag filters with visual tag pills.

## Build & Development Commands

### Setup (after cloning)

```bash
npm install
npm run build
```

### Development (with file watcher)

```bash
npm run dev
```

Watches `shared/content.js` and `shared/content.css`. On every save:
1. Rebuilds (readable + inline sourcemaps) into `chrome/shared/` and `safari/.../Resources/`
2. Prints a reminder to reload the extension in Chrome

**To reload the extension after a build:**
- Chrome: go to `chrome://extensions`, click the **↺ reload** button on Backpack by Label Vier
- Safari: rebuild in Xcode (⌘R) — Xcode picks up the new files automatically

### Production Build

```bash
npm run build
```

Minifies JS (~20 kB, down from ~52 kB) and CSS into both `chrome/shared/` and `safari/.../Resources/`.

### Package Chrome Extension

```bash
npm run package:chrome
```

Runs a production build, then zips `chrome/` → `build/chrome/backpack-by-label-vier-v{version}.zip`.
Upload that file to the Chrome Web Store.

### Package Safari Extension

1. Open `safari/Backpack by Label Vier/Backpack by Label Vier.xcodeproj` in Xcode
2. Run `npm run build` first to ensure the latest files are in Resources/
3. Product → Archive in Xcode
4. Export `.app` to `build/safari/` for App Store submission

## File Synchronization Strategy

### ⚠ Build — Do Not Edit Generated Files

`content.js` and `content.css` in `chrome/shared/` and `safari/.../Resources/` are **generated by the build script**. They are git-ignored and will be overwritten on the next build.

**Always edit only in `/shared/`.**

| Location | Status |
|---|---|
| `shared/content.js` | ✅ Source of truth — edit here |
| `shared/content.css` | ✅ Source of truth — edit here |
| `chrome/shared/content.js` | ⚠ Generated — do not edit |
| `chrome/shared/content.css` | ⚠ Generated — do not edit |
| `safari/.../Resources/content.js` | ⚠ Generated — do not edit |
| `safari/.../Resources/content.css` | ⚠ Generated — do not edit |

### After `git pull`

Always run `npm install && npm run build` after pulling to regenerate the output files.

## Code Style Guidelines

### Language & Approach
- **Vanilla JavaScript** (ES6+) — no frameworks, no TypeScript
- **Strict mode**: All code runs in an IIFE with `'use strict'`
- **Browser APIs only**: DOM APIs, MutationObserver, localStorage, sessionStorage
- **Basecamp integration**: Targets Basecamp 4's DOM structure and Turbo events

### Code Organization
- **Section headers**: Use ASCII art separators for major sections:
  ```javascript
  // ──────────────────────────────────────────────
  // Section name
  // ──────────────────────────────────────────────
  ```
- **Single file**: All logic in one `content.js` file
- **Top-down flow**: Constants → utilities → core features → initialization

### Naming Conventions
- **Constants**: `SCREAMING_SNAKE_CASE` (e.g., `LOG_PREFIX`, `FILTER_BAR_ID`, `TAG_REGEX`)
- **Functions**: `camelCase`, descriptive verbs (e.g., `renderTagPills`, `extractTags`, `scanPersons`)
- **Variables**: `camelCase` (e.g., `tagCounts`, `assigneeMap`, `authorMap`)
- **CSS classes**: BEM-style with `bkf-` prefix (e.g., `bkf-filter-bar`, `bkf-dropdown__menu`, `bkf-tag-pill`)
- **Data attributes**: `data-bkf-*` (e.g., `data-bkf-tags`)
- **DOM IDs**: Kebab-case with `bkf-` prefix (e.g., `bkf-assignee`, `bkf-author`, `bkf-tag`)

### Functions
- **JSDoc comments**: Add doc comments for complex functions
  ```javascript
  /**
   * Extract all tags from a text string. Returns array of normalized tag strings.
   */
  function extractTags(text) { ... }
  ```
- **Pure functions**: Prefer pure functions for data transformations
- **Return early**: Use early returns to reduce nesting

### Error Handling
- **Logging**: Use custom logging functions with prefix
  ```javascript
  const LOG_PREFIX = '[BKF]';
  const log = (...args) => console.log(LOG_PREFIX, ...args);
  const warn = (...args) => console.warn(LOG_PREFIX, ...args);
  ```
- **Null checks**: Always check for element existence before manipulation
- **No try-catch**: Code relies on null checks rather than exception handling

### CSS
- **BEM naming**: Block-Element-Modifier with `bkf-` prefix
- **Basecamp matching**: Match Basecamp's visual style (colors, fonts, spacing)
- **z-index layering**: filter bar: 10, dropdown: 999

## Testing

### Manual Testing Workflow
1. Edit `shared/content.js` or `shared/content.css`
2. The watcher (`npm run dev`) rebuilds automatically
3. Reload the extension in Chrome (`chrome://extensions` → ↺)
4. Navigate to a Basecamp card table: `https://3.basecamp.com/*/buckets/*/card_tables/*`
5. Check browser console for `[BKF]` log messages

### Test Scenarios
- **Filter dropdowns**: Select assignee/author/tag filters, verify cards hide/show
- **Tag pills**: Verify tags render on cards, detail pages, and in edit mode
- **Tag editor**: Add/remove tags using the picker in edit mode
- **Column counts**: Verify counts update when filtering (e.g., "(5/12)")
- **Turbo navigation**: Navigate between pages, verify filters persist/reset correctly
- **Edge cases**: Empty boards, unassigned cards, cards with no tags

### Agent Testing (Browser Console Injection)

AI agents with browser access can test changes without reloading the extension by injecting code directly via the console. Since `content.js` is minified in production builds, use `npm run build -- --dev` first for readable output.

#### Inject JS (from `shared/content.js`)
```javascript
// Run in browser console on a Basecamp card table page
// (paste the contents of shared/content.js)
```

#### Inject CSS
```javascript
document.getElementById('bkf-injected-styles')?.remove();
const s = document.createElement('style');
s.id = 'bkf-injected-styles';
s.textContent = `/* contents of shared/content.css */`;
document.head.appendChild(s);
```

**Note**: since `content.js` runs in an IIFE, re-executing it accumulates event listeners. Reload the page between full injection tests.

## Browser Compatibility

- **Chrome**: Manifest v3, tested on Chrome 120+
- **Safari**: Safari Web Extension, tested on Safari 17+
- **Target**: Basecamp 4 only (`https://3.basecamp.com`)

## Key Constraints

- Vanilla JS only — no TypeScript, no framework
- esbuild is only used to minify/copy; there is no bundling (the file is self-contained)
- Must not break Basecamp's native functionality
- Must handle Turbo navigation (SPA-style page loads)
- Must be visually consistent with Basecamp's design system
- Must persist filter state across navigations (localStorage + URL hash)
